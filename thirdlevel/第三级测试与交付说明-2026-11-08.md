## 1. 当前交付范围

第三级首版支持在用户主动授权后采集当前屏幕，并完成：

```text
MediaProjection 截取屏幕
→ ImageReader 获取画面
→ 本地中文 OCR
→ 降采样 JPEG
→ 第三级 Node 风险服务
→ 视觉模型分析
→ 悬浮窗和通知显示风险
```

本版本同时保留 `/api/v1/risk/text` 文本接口，供只获得 OCR 文本的客户端使用。腾讯会议白板上的手写内容无法稳定通过 OCR 获取，因此第三级 Android 客户端实际使用 `/api/v1/risk/screen` 图片接口。

音频采集已作为可选支路加入。Android 使用 `AudioPlaybackCapture` 采集目标应用允许采集的播放音频，服务端完成语音转写和风险分析。腾讯会议可能禁止采集或使用系统不允许播放采集的音频类型，因此音频仍属于“设备实测后决定是否可用”的能力。

## 3. Android 实现

| 文件 | 作用 |
| --- | --- |
| `ThirdLevelActivity.java` | 服务地址、令牌、悬浮窗和 MediaProjection 授权 |
| `ScreenRiskService.java` | 前台服务、截屏、OCR、视觉分析、风险状态 |
| `AppAudioCapture.java` | AudioPlaybackCapture、PCM 分片和 WAV 封装 |
| `ScreenTextRecognizer.java` | ML Kit 中文 OCR |
| `ImageDeduplicator.java` | 用 64 位差值哈希跳过相同画面 |
| `RiskApiClient.java` | 调用文字或图片风险接口，失败重试一次 |
| `RiskOverlayController.java` | 右上角可滚动悬浮窗 |
| `TextDeduplicator.java` | OCR 文字去重工具 |
| `RiskModels.java` | 请求和结果模型 |

当前参数：

- 截屏采样周期：2 秒；
- OCR 最大长边：2600 像素；
- 发送服务端的图片最大长边：1600 像素；
- JPEG 质量：65；
- 客户端请求超时：15 秒；
- 音频段长约 10 秒，保留 0.5 秒重叠；
- 音频格式：16 kHz、单声道、PCM 16 位 WAV；
- 音频请求读取超时：30 秒；
- 网络错误或 5xx 最多重试一次，沿用同一个 `request_id`；
- 截图只在内存中处理，不保存原始截图；
- 悬浮窗使用 `FLAG_SECURE`，避免把风险提示本身再次作为风险画面识别；
- 画面或 OCR 文字变化后重新分析；
- 风险在新画面连续两次无风险后才清除；
- 画面和语音各自维护风险状态，一路正常不会错误清除另一路的风险。

## 4. Node 服务

接口：

- `GET /health`
- `POST /api/v1/risk/text`
- `POST /api/v1/risk/screen`
- `POST /api/v1/risk/audio`

服务端负责：

- 保存外部模型 API Key；
- Bearer 测试令牌认证；
- 请求字段和 JPEG 格式校验；
- 12 秒文字分析超时、10 秒视觉分析超时、12 秒语音转写超时；
- `request_id` 幂等缓存和冲突处理；
- 输出 `none/low/medium/high`、`evidence`、`reason`；
- 分析失败时不返回 `risk_level`。

外部模型密钥和测试令牌只从环境变量读取。仓库不包含 `.env`。

### 5.4 腾讯会议白板测试

纯 OCR 首次测试只得到工具栏文字，共 34 个字符：

```text
折叠、AI画笔、箭头、橡皮擦、撤销、重做、清空、添加白板、更多
```

这说明 ML Kit OCR 能读取普通界面文字，但不能完整读取白板手写笔画。

改用视觉接口后，腾讯会议白板画面曾返回：

- `high`；
- `medium`，证据为“这个理财 百分百收益”。

因此当前版本对腾讯会议白板的处理依赖视觉模型，而不是 OCR 手写识别。

### 5.5 风险状态保持

最终调整后的状态行为是：

- 画面完全不变时，不覆盖现有结果；
- 已出现风险时，不会显示“文字未变化”；
- 画面或 OCR 文字变化后，立即重新分析；
- 新画面连续两次返回无风险后，清除旧风险并显示“检测正常”；
- 分析期间旧风险不会马上消失；
- 如果分析服务暂时失败，已有风险提示继续保留，并附带失败原因。

真机验证：

1. 打开固定转账风险图片，通知显示“发现风险：高风险”；
2. 保持 15 秒不动，风险提示持续存在；
3. 切换到普通会议图片，第一次无风险结果仍暂保留风险；
4. 第二次无风险结果后，通知约 4 秒内切换为“无风险”。

### 5.8 画面与语音联合测试

在同一个检测会话中：

1. 播放包含“公安局、洗钱、安全账户”的诈骗语音；
2. 同时切换到包含“安全账户、确认转账”的风险画面；
3. 日志分别出现 `screen risk result: high` 和 `audio risk result: high`；
4. 顶部标题显示“存在风险”，下方再显示分析内容：

```text
存在风险
风险等级：高风险

画面：收款人：安全账户（资金核查专户）……
语音：我是公安局的……请把钱转到我们的安全账户……
```

画面和语音两路检测能够同时运行，风险状态不会互相覆盖。

### 5.9 结论优先显示与组合测试

界面标题限制为短结论，避免长标题吞字：

- 任意一路存在风险：红色标题“存在风险”；
- 两路均正常：绿色标题“无风险”；
- 采集或分析不可用：橙色标题“检测受限”。

两路组合的行为如下：

| 画面 | 语音 | 标题 | 分析区 |
| --- | --- | --- | --- |
| 正常 | 正常 | 无风险 | 画面未发现风险；语音未发现风险 |
| 风险 | 正常 | 存在风险 | 显示画面风险证据，同时显示语音正常 |
| 正常 | 风险 | 存在风险 | 显示语音风险证据，同时显示画面正常 |
| 风险 | 风险 | 存在风险 | 分别显示画面和语音风险证据 |

正常语音播放结束后，如果后续没有捕获到声音，会保留“上次分析正常”的说明，不会把状态直接当成风险。

## 6. 已解决的问题

1. 明确 `WindowManager` 不能读取其他应用画面，改用 `MediaProjection`。
2. 第三级代码与一、二级隔离存放，便于搭档替换采集和 UI。
3. ImageReader 在华为平板上偶发不回调，改为后台定时主动取最新帧。
4. 白板手写内容无法 OCR，增加屏幕图片视觉分析。
5. OCR 失败时仍继续发送图片分析，不再直接终止。
6. 固定宽度和 6 行限制导致分析结果显示不全，改为可滚动全文。
7. 画面未变化时会覆盖风险提示，改为保留最后一次风险状态。
8. 重新进入页面会丢失最后结果，改为保存当前会话状态。
9. 风险结果可能瞬时波动，增加本会话 `medium/high` 风险锁存。
10. 外部模型 Key 不进入第三级客户端；交付 APK 使用占位参数构建。
11. 实时性不足：每次采样都执行 OCR，并降低画面变化阈值，2 秒检测一次。
12. 清空文字后风险不消失：改为新画面连续两次无风险才清除。
13. 服务离线时进入检测后才报错：增加开始前 `/health` 连接检查。
14. 服务端视觉分析超时从 18 秒降到 10 秒，低于客户端 15 秒超时。
15. 增加可选应用播放音频采集、10 秒 WAV 分片、语音转写和风险分析。
16. 画面与语音分别维护风险状态，避免两种来源互相覆盖。

## 7. 待解决问题

1. **视觉模型结果仍有波动。**
   同一白板区域在模型只能看到工具栏时可能返回 `none`。当前通过连续两次无风险才清除来降低误清提示的概率，但仍需用完整演示样例测试。

2. **动画画面会触发较多视觉请求。**
   会议人头像、光标和白板动画可能让画面哈希持续变化。后续可按效果调整哈希阈值、采样周期或增加请求节流。

3. **受保护画面无法采集。**
   `FLAG_SECURE`、DRM 或厂商限制可能导致黑色画面；这不是 OCR 或模型错误。

4. **腾讯会议内部音频是否可采集仍需实测。**
   `AudioPlaybackCapture` 只接受目标应用允许的 MEDIA、GAME 或 UNKNOWN 播放类型。腾讯会议如果使用系统语音通信类型或主动禁止采集，只能提示“语音采集不可用”，不能强取。

5. **尚未验证横竖屏切换。**
   当前虚拟显示尺寸在检测开始时确定，旋转后建议停止并重新开启检测。

6. **Android 单元测试执行器异常。**
   测试源码可以编译，但当前 Windows + Gradle 9.3.1 环境执行 `testDebugUnitTest` 时报 `GradleWorkerMain ClassNotFoundException`，属于测试运行环境问题，暂以编译和 Node 测试替代验证。

7. **服务端幂等缓存为单实例内存缓存。**
   服务重启后缓存消失，多实例部署需要 Redis 或数据库。

8. **测试服务使用局域网 HTTP。**
   正式部署需要 HTTPS、随机令牌、访问控制和密钥轮换。

## 8. 本地运行

服务端：

```powershell
cd E:\桌面\HNU\hnu_FinRiskEye\thirdlevel\server
.\start-local.ps1
```

`start-local.ps1` 会优先读取环境变量 `AI_API_KEY`；本地有被忽略的 `gradle.properties` 时也可从中读取。未找到时会要求在当前 PowerShell 窗口输入密钥，不写入文件。服务窗口必须保持运行，关闭窗口后 Android 会提示无法连接。

也可以根据 `.env.example` 手动创建 `.env` 后执行 `npm start`。

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:3100/health
```

Android：

1. 安装 `app-debug.apk`；
2. 平板和电脑连接同一局域网；
3. 在第三级页面填写 `http://<电脑局域网IP>:3100`；
4. 填写与 `RISK_API_TOKEN` 相同的令牌；
5. 授予悬浮窗和通知权限；
6. 如需语音，勾选“同时采集应用播放音频”并授予录音权限；
7. 点击“开始跨应用风险检测”；
8. 在系统窗口中允许屏幕共享。

如平板无法连接，请检查电脑防火墙是否允许 TCP 3100。

## 9. 隐私和处理边界

- 开始检测前必须取得会议参与者同意。
- 截图只在内存中降采样，不写入客户端文件。
- 降采样截图和 OCR 文字会发送到自建风险服务，再由服务端发送到外部模型供应商。
- 勾选语音检测后，约 10 秒的应用音频片段会发送到自建风险服务和外部语音转写服务。
- 测试样例不得包含真实身份证、银行卡、验证码、密码或未授权会议内容。
- 外部模型 Key 只保存在服务端环境变量。
