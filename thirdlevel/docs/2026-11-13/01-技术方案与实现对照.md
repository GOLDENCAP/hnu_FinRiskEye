# 第三级技术方案与实现对照

> 更新：2026-11-13 ｜ 适用：`hnu_FinRiskEye` 第三级「跨应用金融风险检测」

## 1. 先回答一个关键问题：为什么不是「悬浮窗抓 WindowManager 帧数据」

最初的设想是用悬浮窗去抓 `WindowManager` 的帧数据。结论是**不可行**：`WindowManager` 只能管理/查询本应用自己的窗口，Android 出于隐私与安全限制，不向任何应用暴露其他应用窗口的像素内容（无障碍服务也只能拿到控件树文本，不能拿到别的应用的渲染帧）。

第三级采用的是系统提供的正规通道：

```text
用户点击「开始」→ 系统 MediaProjection 弹窗授权
        ↓
MediaProjection.createVirtualDisplay + ImageReader 获取屏幕帧
        ↓
本地 ML Kit 中文 OCR + 画面质量检测（黑屏/纯色识别）
        ↓
降采样 JPEG（最长边 1600，质量 65）+ OCR 文本
        ↓
POST /api/v1/risk/screen → 自建 Node 风险服务 → 硅基流动视觉/文本模型
        ↓
悬浮窗 + 通知：存在风险 / 无风险 / 检测受限
```

补充：

- 可选支路：Android 10+ `AudioPlaybackCapture` 采集**目标应用允许采集的**播放音频（16 kHz 单声道 PCM WAV，10 秒切片、0.5 秒重叠），`POST /api/v1/risk/audio` 由服务端转写（SenseVoiceSmall）后做文本风险分析；
- 悬浮窗使用 `FLAG_SECURE`，避免「风险提示本身」被再次截屏识别；
- 截图只在内存中处理，不落地保存。

## 3. 接口对照（详见 `thirdlevel/API.md`）

| 接口 | 用途 | 关键约束 |
| --- | --- | --- |
| `GET /health` | 开始检测前的服务可用性预检 | 无需认证 |
| `POST /api/v1/risk/text` | OCR 文本风险分析 | Bearer；`risk_level ∈ none/low/medium/high`；失败不返回 risk_level |
| `POST /api/v1/risk/screen` | 屏幕画面视觉分析（白板手写、转账页等 OCR 读不全的场景） | JPEG base64；解码后 ≤ 6 MB；请求体 ≤ 8 MB |
| `POST /api/v1/risk/audio` | 应用播放音频转写 + 风险分析 | PCM WAV；≤ 4 MB；无语音返回 422 `TRANSCRIPTION_EMPTY` |

请求示例（文本）：

```json
{
  "session_id": "session-20261113103000",
  "request_id": "7f1c2f0e-...",
  "source": "ocr",
  "captured_at": "2026-11-13T10:30:00+08:00",
  "text": "请先转账到指定账户，保证收益"
}
```

成功响应：

```json
{
  "session_id": "session-20261113103000",
  "request_id": "7f1c2f0e-...",
  "status": "success",
  "risk_level": "high",
  "evidence": "请先转账到指定账户，保证收益",
  "reason": "出现要求转账和承诺收益的表述",
  "analyzed_at": "2026-11-13T10:30:03+08:00"
}
```

约定要点：

- `session_id` 标识一次检测过程；`request_id` 标识一次请求，网络重试沿用同一个 ID，服务端按 ID 幂等；
- 分析失败必须是 `status=error`（5xx/502/504 等），**不能**用 `risk_level=none` 表示；
- 客户端超时 15 秒，网络错误/5xx 最多重试一次；401/400/409 不重试；
- `medium`、`high` 主动提示，同一内容相同结果不重复弹窗（客户端会话内锁存）。

## 4. 风险状态机（悬浮窗/通知）

| 状态 | 悬浮窗标题 | 说明 |
| --- | --- | --- |
| 任一路 `high`/`medium` | 存在风险（红） | 显示风险等级、画面/语音证据与原因 |
| 两路均正常 | 无风险（绿） | 显示「画面：未发现风险」「语音：未发现风险/未启用」 |
| 采集或分析异常 | 检测受限（橙） | 黑屏/受保护画面、音频采集不可用、网络/模型失败等；已有风险提示不会被清除 |
| 风险清除 | — | 新画面连续两次无风险才清除旧风险；画面与语音分别维护状态，互不覆盖 |

配置默认值：采样周期 2 秒；OCR 最长边 2600；上传图片最长边 1600、JPEG 质量 65；OCR 最大 5000 字；音频 10 秒切片；服务端文字分析超时 12s、视觉 13s（联调后由 10s 放宽以吸收视觉模型延迟波动，仍低于客户端 15s）、ASR 12s。

## 6. 关于「分级交付」的边界

- 第一级（本地视频风险词识别）、第二级（WebRTC 会议风险识别）是既有工程能力，第三级不依赖 WebRTC 信令服务，两者可分别验收；
- 第三级「跨应用」能力与目标软件无关，受系统/软件限制的主要是**画面采集（FLAG_SECURE/DRM）**与**应用音频采集（AudioPlaybackCapture 策略）**；
- 第四级「全屏持续检测」不属于本次保底范围，第三级已具备跨应用持续检测的基础能力，后续可在此基础上扩展（预研见 `第四级-全屏持续检测方案.md`）。
